# Адмінка кейсів

Адреса: **`/admin/`** (наприклад, `https://ваш-домен/admin/` або локально `http://localhost:8000/admin/`).

## Режими роботи

| Режим | Коли активний | Де живуть дані |
|---|---|---|
| **demo** | ключі в `site/js/supabase-config.js` порожні | localStorage браузера (файли — data:URL) |
| **supabase** | ключі заповнені | Supabase Database + Storage |

У демо-режимі вхід: `admin@demo.local` / `admin123` (підказка показується на сторінці входу). Демо-дані видно тільки у вашому браузері — цей режим призначений для локальної перевірки.

## Підключення Supabase (один раз, ~10 хв)

1. Створіть проєкт на [supabase.com](https://supabase.com) (безкоштовний тариф достатній).
2. **SQL Editor** → вставте вміст `supabase/schema.sql` → **Run**. Це створить таблицю `cases`, RLS-політики, тригер `updated_at` і Storage-бакет `case-media`. Розкоментуйте блок `insert` наприкінці, якщо хочете одразу перенести поточні кейси сайту.
3. **Створення першого адміністратора:** Authentication → Users → **Add user** → вкажіть email і пароль, увімкніть **Auto confirm**. Це і є логін для входу в адмінку.
4. Закрийте самостійну реєстрацію: Authentication → Sign In / Up → вимкніть **Allow new users to sign up** (щоб ніхто не міг створити собі акаунт і отримати права на запис).
5. Скопіюйте **Project URL** і **anon (public) key** із Settings → API у `site/js/supabase-config.js`:

```js
window.SUPABASE_CONFIG = {
  url: "https://xxxx.supabase.co",
  anonKey: "eyJ..."
};
```

6. Задеплойте зміни. Готово: адмінка пише в базу, сайт читає з бази.

## Безпека

- Пароль адміністратора зберігається лише в Supabase Auth — у коді його немає.
- `anon key` — публічний ключ; усі права визначають RLS-політики:
  - анонімні відвідувачі: **тільки читання** кейсів зі статусом `published` і файлів бакета;
  - авторизовані користувачі: повний CRUD таблиці `cases` і бакета `case-media`.
- `service_role` ключ ніде у фронтенді не використовується і не повинен.

## Що вміє адмінка

- список кейсів по категоріях: прев'ю, назва, опис, №, статус, дата оновлення;
- створення / редагування (назва, опис, посилання, категорія, порядок, статус, «нова вкладка»);
- завантаження зображення (JPG/PNG/WEBP) і hover-відео (MP4/WEBM): drag-and-drop, прогрес, прев'ю, заміна, видалення; замінені й осиротілі файли чистяться зі Storage;
- живий попередній перегляд картки (з hover-відео);
- перемикач публікації прямо в списку;
- зміна порядку: drag-and-drop у межах категорії або стрілки ↑↓;
- видалення з підтвердженням (разом із файлами кейсу).

Сайт показує лише `published`-кейси, відсортовані за `order_index`; поки дані вантажаться — скелетони; якщо база недоступна — вбудований резервний список із коду.
