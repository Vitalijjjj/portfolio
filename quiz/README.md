# Квіз (окремий піддомен)

Повністю автономна сторінка-опитування. **Ніяк не пов'язана** з основним
портфоліо: окрема папка, власний дизайн, власна serverless-функція, окремий
проєкт Vercel і власний піддомен. Спільного коду немає.

```
quiz/
├── index.html      # розмітка
├── quiz.css        # стилі (без залежностей)
├── quiz.js         # логіка: один крок на екран, відправка
├── api/submit.js   # приймає відповіді → надсилає в Telegram
├── vercel.json     # noindex + cleanUrls
└── README.md
```

## Як задеплоїти на піддомен

Оскільки основний сайт — це окремий проєкт Vercel (root = `site/`), квіз
розгортається як **другий проєкт Vercel із того самого репозиторію**:

1. Vercel → **Add New → Project** → імпортувати той самий Git-репозиторій.
2. У налаштуваннях проєкту **Root Directory** вказати `quiz`.
   Framework Preset — **Other** (статика без збірки).
3. **Environment Variables** цього нового проєкту:
   - `TELEGRAM_BOT_TOKEN` — той самий токен бота, що й на основному сайті
   - `TELEGRAM_CHAT_ID` — id чату для заявок (напр. `-5289373638`)
   - `QUIZ_NAME` *(необов'язково)* — підпис у повідомленні, напр. `Опитування Instagram`
4. Deploy.
5. Проєкт → **Settings → Domains** → додати піддомен, напр.
   `kviz.alphadigitalua.com` або `opytuvannya.alphadigitalua.com`,
   і додати відповідний CNAME у DNS (Vercel підкаже запис).

Готово: квіз живе на своєму піддомені, відповіді падають у той самий
Telegram-чат окремим форматованим повідомленням («📋 НОВЕ ОПИТУВАННЯ»),
щоб не плутати з заявками з сайту («🟢 НОВА ЗАЯВКА»).

## Захист від спаму

У функції `api/submit.js` вже вбудовано:
- перевірку джерела запиту (лише зі свого піддомену),
- rate-limit (4 запити/хв з IP),
- honeypot-поле + мінімальний час заповнення (3 с).

## Змінити питання

Усі питання — у масиві `STEPS` на початку `quiz.js`. Типи кроків:
`text`, `tel`, `textarea`, `choice` (варіанти, опційно з полем «Інше»),
`rating` (шкала 1–10). Поле `required: true` робить крок обов'язковим
(зараз обов'язкові лише ім'я та телефон).
